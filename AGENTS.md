# Working on this portfolio

Keep the System 7 visual language consistent. Use the shared typography, icon sizes, paper/chrome colours and bevelled controls in `src/app/system7.css`. Preserve the hard window shadows. Scientific plots, game boards and instrument states can retain colours that communicate their data.

Render interface icons with `System7Icon` and register app/project identities in `src/lib/iconIdentity.ts`. Reuse each subject's canonical PNG for desktop, menus, Finder and app interiors; COVERD uses its original owned logo on a white backing. The renderer centers measured alpha bounds at 90% of a square frame without changing proportions. Keep `src/lib/system7IconBounds.ts` consistent with the real images. Use 16px for inline/menu/navigation icons, 32px for cards, Finder results, Contact destinations and the phone window switcher, and 48px for desktop launchers and primary project headings. New identities require explicit entries; avoid alternate SVG miniatures, emoji artwork and generic fallbacks. Keep generated PNGs at their authentic native resolution; do not shrink an art field and enlarge it afterward. Use pixelated sampling without smoothing, and version changed image URLs to refresh caches. The top-left black person mark and official institution vector logos are explicit branding exceptions to the generated subject family. Keep prompts and hashes in `docs/SYSTEM7_ICON_PROMPTS.json`, then run `npm run check:icons` and the compiled icon browser audit for affected surfaces.

Window and Find title bars have a centered text-only title with a solid clearing and a bounded 14px gray stripe band. Preserve the larger touch hit areas without stretching the stripe pattern across their full height. The active application icon belongs in the right side of the main menu bar. Review real narrow-screen screenshots as well as source checks; passing decoding and dimensions does not establish visibility.

For new experiences, education, capabilities or documents, follow [the profile graph workflow](docs/KNOWLEDGE_GRAPH_WORKFLOW.md). Read the supplied evidence first, then add records and stable references to `src/data/profile.ts` and `src/data/documents.ts`. Declare a new record's direct `projectSlugs` and `relatedProjectSlugs` there once. The shared resolver and graph adapter update profile links, project provenance, graph navigation and export automatically.

Connect each capability to concrete project or role evidence and named sources. Keep direct work distinct from related research. Dates and similar technology names do not establish provenance. Preserve stated qualifiers such as a predicted degree result. Read an uploaded LinkedIn export before using it; unavailable pages cannot substantiate new claims. Private files can inform a record but must not become public URLs.

Add reviewed copy for all four locales. Keep existing anchor and graph IDs stable. Review affected browser journeys, including source documents, keyboard navigation and a narrow mobile window.

Update `docs/VERIFICATION.md` and `continue.md` with the actual scope of verification. Preserve unrelated working-tree changes.
